Prepare works on the project folder itself. It adds any packages the code imports that are missing from requirements.txt (making code/requirements.txt if there is none), creates the project's venv, installs requirements.txt into it, checks that each package can be imported, and adds the launchers run.sh and run.bat (both, so a release runs on Linux and Windows) where they are missing. Run it again after changing the imports.

Packages only one platform needs go in requirements-linux.txt / requirements-windows.txt next to requirements.txt: Prepare puts a new import there when a platform check guards it (e.g. under if sys.platform == "win32":, or a flag made from one), installs and checks only this computer's files, and run.sh / run.bat install their platform's file as well. A package already in any of the three files stays where it is - move a line to the right file once if Prepare put it in the wrong one. A DWC plugin lists requirements-linux.txt in plugin.json too.

With Create standalone ticked (in the project options), the launchers go into a standalone/ folder at the top of the git repository instead, with source.txt (this project folder, whose files are at the top of the ZIP) and exclude.txt (what to leave out - for a DWC plugin, plugin.json and sd/). Commit the folder: the release workflow then also releases a standalone ZIP that runs without DWC - for a program with no plugin.json, that ZIP is its release. Prepare makes its own launchers again each time, so a new main program reaches them; remove the (made by Prepare in Prep_and_Package) comment from one to keep your own changes to it.
