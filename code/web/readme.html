Instructions

Welcome. No settings have been saved yet, so the DWC versions folder and the plugins folder are both set to the folder this app is installed in (...). Open Settings and point them at the right folders.

These tools help with DuetWebControl (DWC) plugin development on a Raspberry Pi or a Windows PC. There are two:

  • Create DWC Version downloads a DWC release from GitHub, installs its dependencies and starts its dev server.
  • Create a Plugin builds or zips one of your plugins into an installable .zip.

They run as separate jobs, so the DWC dev server can keep running while you build plugins.

Setup

__SETUP__

The app prints the address to use when it starts, and on a desktop session your browser opens there by itself. By default it listens on this computer's network address (so localhost will not work) on the preferred port from the Settings page if that port is free, or otherwise on the first free port from 17800. Any computer on the same network can open that address, which is what you want on a Pi without a screen. There is no login, so anyone who can reach the page can run builds and change the folders: only use it on a network you trust. If you only use the app from this computer's own browser, set Listen on to This computer only on the Settings page. The app then listens on 127.0.0.1, and no other computer can open it. On the network setting, this computer needs a network connection when the app starts, so that it has an address to use.

Folders

Both tools expect this layout. Create a Plugin only lists what is already there, and Create DWC Version creates the DWC version folders for you. Until you set them on the Settings page, both folders are the folder this app is installed in, so a downloaded version such as 3.7 appears right next to plugin_tools.py. (That folder must be writable, or Create DWC Version cannot download into it: pick another folder in Settings if it isn't.) Only folders named like a DWC version (starting with a digit, such as 3.5.1) are listed as versions, and a plugin is listed once it has at least one plugin version folder. A plugin version folder can have any name (such as plugin3.7.x or Version1): it is any sub-folder of the plugin's folder with a Code folder, the folder holding plugin.json. That is the plugin version folder itself or a folder up to 3 levels below it, such as Code (node_modules, dist, pkg, venv and hidden folders are not searched). Other sub-folders, such as Documents, are not listed.

The Settings page also has the Preferred port for this tool's own web page. 0, the default, means no preference: the first free port from 17800 is used. A change takes effect the next time the app starts. This tool is currently running at ....

Create DWC Version: get a DWC version running

  1. Choose a version in the list, or choose New version… and type one, such as 3.5.1 or 3.6-dev. Start with a digit and do not type a leading v. It must match a release tag (v3.5.1) or branch on the DuetWebControl repository.
  2. Press Start. It runs git clone, npm install, npm audit and then the dev server, and shows the output as it goes. Audit findings are shown but don't stop the job. The dev server command depends on the version: npm run dev (Vite) for 3.7 and later, and npm run serve for older versions such as 3.5.1 or 3.6-dev.
  3. When the dev server prints its Local: address, the tool checks that address. As soon as it answers HTTP 200 the job is finished OK and the status shows where the server is running. It does not wait for any further bundling. The server keeps running, and the rest of its output keeps appearing in the log. The older servers print their address after the first compile has finished, which can take a while on a Pi.
  4. Press Stop to shut the dev server down. You can't start another version while it is running.

Choosing a version that is already downloaded deletes that folder and downloads it again. You are asked to confirm first. If the address doesn't answer 200 within 30 seconds, the log says so and the job just carries on waiting until the server exits or you press Stop.

Create a Plugin: build or zip a plugin

  1. Choose the DWC version, the Plugin and its Version.
  2. Check the Code folder: the folder holding plugin.json, relative to the plugin version folder (. is that folder itself). It is filled in with the first one found. If a plugin version has plugin.json in more than one place, the others are listed under the box and offered as you type. Type another folder to use that instead: it is remembered for that plugin version once you press Build. Automatic goes back to the one found.
  3. Press Build. What happens depends on the plugin's plugin.json:
    • No dwcVersion entry (for example a plugin that only runs on the Pi): the contents of the Code folder are zipped. No build is needed.
    • dwcVersion present: the plugin is built against the DWC version you chose, using that version's scripts/build-plugin.js. Old dist and pkg folders and any __pycache__, *.pyc and *.log files in the plugin version folder are cleared first.
  4. The result is written in the plugin version folder (the one containing plugin.json or the Code folder) as <plugin name>-<manifest version>.zip (the version from plugin.json), and the log ends with its size and path. Any older .zip files in that folder are removed. From DWC 3.7, a build of a stable plugin version (one without -beta, -rc ...) also makes <plugin name>-<manifest version>-srcmap.zip, the source maps kept out of the plugin zip for looking up error stack traces. It is put next to the plugin zip and is not needed to install the plugin.

Leaving files out

These are always left out of a zip: __pycache__ and venv folders, *.log and *.pyc files. To leave out more, open Exclude files, which lists every file under the Code folder, and tick the ones you don't want.

  • For a zip-only plugin, ticked files are left out of the zip. Nothing on disk changes.
  • For a real build, ticked files are moved out of the Code folder while the build runs and put back afterwards, even if the build fails or you press Stop.
  • Your ticks are remembered separately for each DWC version, plugin and plugin version combination.

What is remembered

The selections you used last time in each tool come back as the defaults, the ticked files are remembered per combination (above), and the two folders are kept until you change them. They are all stored in one settings file, which is currently ....

Where the settings file is. By default it is .plugin_build_exclusions.json in the install folder (the folder holding run.sh / run.bat). __HIDDEN_NOTE__ Things to know:

  • It is not created when the app first starts. It appears the first time you save on the Settings page or press Build or Start. Until the file exists, the app opens on this page.
  • That folder must be writable, or nothing can be saved. The app warns at start-up if it isn't.
  • If you move or copy the app to another folder, take the code folder and the settings file with it.
  • Moving your DWC versions or plugins folders does not move the file. Use Settings to point the tools at the new folders.
  • It is plain text, so you can back it up or delete it. Deleting it resets everything to the defaults.

Stop and Exit

  • Stop ends the running job in that tool, including the dev server if it is running.
  • Exit stops everything and shuts the app down. The app also shuts itself down, stopping any job and the DWC dev server, when every one of its tabs has been closed: about 10 seconds after the last tab closes, or up to about 2 minutes if the browser was closed without warning (for example after a crash). Reloading a page or moving to another page of the app does not count as closing it. Until a browser has opened the app, it keeps running.
  • The Home page shows which tools are currently running.
