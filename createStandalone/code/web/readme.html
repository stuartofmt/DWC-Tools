Instructions

Welcome. No settings have been saved yet. Browse starts in ...: change that on the Settings page if your projects live somewhere else.

These tools prepare and release standalone Python programs, on a Raspberry Pi or a Windows PC. There are two, normally used in this order:

  • Prepare gets the project folder ready: it works out requirements.txt from the program's imports, creates the project's Python venv, installs requirements.txt into it with pip and checks that every package can be imported.
  • Make Zip builds the project's release zip in its dist folder, ready to copy to another computer.

They run as separate jobs, so both can run at the same time. Nothing is installed system-wide (no apt, no sudo): every package goes into the program's own venv, using the venv's pip. That works on Linux versions whose system Python is "externally managed" and refuses pip install.

What a project looks like

A project is a folder with a code folder holding the program. Its name is the folder's name. Nothing else needs adding: Prepare makes the rest.

scanCam/                   the project folder: its name is the project's name
    README.md              optional, copied with the program
    code/
        scanCam.py         the main program, which may set its version: progVersion = '1.0.0'
        requirements.txt   what pip installs into the venv: made by Prepare (it can also be in the project folder)
        ...                everything else in code is copied too
    venv/                  made by Prepare (never part of the zip)
    run.sh                 made by Prepare if there is none (Windows: run.bat): starts the program with the venv
    dist/                  made by Make Zip

Choosing the project

  • Type the full path of the project folder, or pick one of the recent projects the box offers, or
  • press Browse…. Click a folder to open it and ↑ Up to go to its parent. Project folders are shown in bold with a project tag. Press Select next to one, or Use this folder for the folder being shown.

The project you choose in one tool is also chosen in the other, and comes back next time. Browse starts next to it.

Project options

Each project has options, under Project options below the project. They are saved as soon as you change them and used by both tools.

  • Main program: the .py file in code that starts the program. It is picked for you when it has the project's name (scanCam.py) or is the only one. If it sets a version, with a line such as progVersion = '1.0.0' (__version__ or VERSION work too), the version goes into the zip's name. A version is not needed.
  • The venv can also use Python packages already installed on the system (ticked by default): the venv then sees packages that came with the operating system, such as picamera2 on Raspberry Pi OS, as well as its own. Untick it for a venv that holds only what requirements.txt lists.

Make Zip needs a requirements.txt, in code or in the project folder: press Prepare to make one.

Prepare

  1. Choose the project and press Prepare. The line above the button shows what the project has now.
  2. requirements.txt. Every .py file in code is read for its import lines. Python's own modules and the project's own modules (any .py file or folder in code) are skipped. Each other import is turned into the pip package that provides it, as recorded by the packages installed on this computer (for example yaml comes from PyYAML), or guessed from a short list of well-known names when it is not installed here (cv2 is opencv-python). The packages that are missing are added to the project's requirements.txt, which is made in code if there is none. Nothing already in it is changed or removed, so your own additions and version pins stay. Packages it lists that nothing imports are reported. An import inside try: ... except ImportError: is optional, as the program copes without it: it is reported but not added.
  3. venv. The project's venv folder is created (with the system packages option above), or the existing one is used. A venv made with the other setting of that option is made again.
  4. Install. requirements.txt is installed into the venv with the venv's own pip.
  5. Check. The venv imports each package the program needs. A failure means something is missing from requirements.txt, or the package needs something from the operating system: the log shows the error.
  6. Launcher. run.sh (Windows: run.bat) is added to the project folder, unless there is one already, so the program can be run from there with its venv.

The log ends by listing what Make Zip will use. Run Prepare again whenever the program's imports change.

Creating a venv needs Python's venv module. Debian and Raspberry Pi OS ship it separately as python3-venv: if the log says the venv could not be created, that package is missing and has to be installed once by the system administrator (sudo apt install python3-venv).

Make Zip

  1. Choose the project and press Make Zip.
  2. The zip is dist/<name>-<version>.zip in the project, or dist/<name>.zip when the main program sets no version, and replaces an earlier zip of the same name. It unzips to a <name> folder holding README.md, code (and requirements.txt when it is in the project folder) and an install.py made from the project options (See the install.py these make shows it). __pycache__ and venv folders and *.pyc files are left out.
  3. Zips in dist lists the zips made so far, newest first. Click one to download it.

On the other computer, unzip it and run python3 install.py in the unzipped folder (on Windows: py install.py). It asks for the install folder (the project's name in the home folder if you just press Enter), copies the program there, creates its venv, installs requirements.txt into it and adds run.sh (Windows: run.bat) to start the program with that venv. Running it again updates the program files and recreates the venv.

Stop and Exit

  • Stop ends the running job in that tool, with everything it started (pip ...). A stopped zip is deleted. Stopping Prepare part way can leave the venv without every package: press Prepare again.
  • Exit stops everything and shuts the app down (so does Ctrl+C in the terminal).
  • Closing the page does the same: once every page of the app has been closed, in every browser that had it open, the app stops any running job and shuts down about 10 seconds later. Going to another page of the app, or reloading, does not count. A page that stops answering (for example after the browser crashed) counts as closed after 90 seconds. Until a page has been opened for the first time, the app keeps waiting. So keep a page open while Prepare runs: closing it stops Prepare.
  • The Home page shows which tools are currently running.
